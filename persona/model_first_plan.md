# 让模型干主活：反应式配方（rules → 0 的路线）

> 目标：**完美入戏的模型 + 仅必需规模（或零）的规则层**。
> 本文记录为什么现在的规则层在干大部分的活，以及怎么把它设计掉。

---

## 0 结论

这个目标成立，但不是靠"再训久一点"。三条实测证据指向同一件事：

**现在的模型不是"理解得浅"，是一个按句尾查表的查找器。** 换一种说法、换一个名词，
查表就失效，于是落回 351 条回复的边际分布 —— 观感就是"答非所问 + 车轱辘话"。
规则层不是能力的补丁，是**输入形状没被覆盖**的补丁。

三个动作，按顺序：

| # | 动作 | 治什么 | 实测 |
|---|---|---|---|
| 1 | 目标句 351 → **89** | 退出容量，让"认出名词"有地方学 | 落池 65% ✓ |
| 2 | 回复改成 **回声 + 表态** | 学会"抄对方的名词"→ 对任意输入都有反应 | **抄不出来**（第 6 节） |
| 3 | 句尾不再携带答案信息（交叉生成） | 拆掉"末 2 字查表"这条捷径 | 域内 26%→70% ✓ |

> **一句话修正（下午实测后）**：动作 1、3 成立，动作 2 在 5L/2head 上撞墙。
> 结论不是"目标不成立"，而是**目标要拆成两半**：话术全部归模型（已做到），
> 路由留在规则（模型原理上做不到）。详见第 6、7 节。

## 1 三条证据

### 1.1 换一个名词，模型完全不读输入（`probe_zh_novel.py`，今天测）

同一句式只换名词，各采 4 次：

```
青蛙怎么不动了？   -> 那是咱冻的，等会儿放回去就活了！          ← 对
大妖精怎么不动了？ -> 是大酱，咱最好的朋友！                    ← 跑题
企鹅怎么不动了？   -> 冷才好呢，咱最喜欢冬天了！                ← 胡说
仙人掌怎么不动了？ -> 星星就是四个角，咱天天看星星，错不了！     ← 胡说
```

**四次输出里没有一次复述对方说的词。** 这是"没读输入"最硬的证据：
如果它读了，最省力的反应是先把这个词吐回来。

### 1.2 语料里每条 prompt 的结尾都是唯一的

`raw_canon.jsonl` 7,062 条 / 351 个目标回复，组内**末 2 字熵 4.84 bit**，
而组内平均只有 ~20 条 —— 也就是说**末 2 字足以唯一识别一条 prompt**。
交叉熵梯度会先抓住这个最省力的相关：*记住结尾 → 吐出答案*。
于是：

- 语料原句（原样的结尾）→ 命中 42%
- 换一种说法（换掉的正是结尾）→ 落空，pairwise 归一化 KL 0.15
- 换成没见过的名词 → 落空

### 1.3 容量确实在墙边（这一条以前算错了）

| 目标回复数 | 需要背的信息 | 实测 |
|---|---|---|
| 3,498 | ~569 kbit ≈ **71 KB** | 语料原句命中 0/20，退化成"人设腔 + 几个模板" |
| 351 | ~57 kbit ≈ **7 KB** | 语料原句命中 10/24（42%） |
| 89（新配方） | ~14 kbit ≈ **1.8 KB** | 待测 |

2.17M 个 ternary 权重按 1.58 bit 算 = 3.43 Mbit ≈ **429 KB 理论上限**，
小模型的有效利用率通常只有 5~10% → **21~43 KB**。
上面两行实测正好把它夹在 7 KB 与 71 KB 之间。
（早先记的"每条 13 字 ≈ 12 bit"是算错了，13 字 × log2(1850) = 141 bit。）

**结论：容量不是唯一瓶颈，但"351 条独立整句"已经把钱花在了错误的地方** ——
花在"复现 351 种说法"，而不是"认出对方在说哪个词"。

## 2 新配方：反应式对话

```
回复 = [回声]{刚说的名词} + [表态]{本概念的答案 | 通用回避}
```

格式不动，仍是 `User: {u}\nBot: {a}\n` —— **固件一行不用改**，只换语料。

### 为什么是"回声"

- 回声是**照抄输入里的字**，所以对**任何**没见过的名词都成立。
  这是"我听见了"唯一不依赖知识的证据。
- 信息量从"背一整句"降到"抄 2~4 个字"，剩下的容量全留给"认出是什么"。
- 同一个概念，因为回声不同，每条回复表面都不一样 →
  **多样性来自输入，而不是来自更大的答案池**。这正是"不车轱辘"的正确来源。

### 四路数据（`gen_react_corpus.py`）

| 路 | 量 | 内容 | 教什么 |
|---|---|---|---|
| S1 自然句 | 3,942 | canon 里的域内行，答案限定在该概念 3 条内 | 真人语感 |
| S2 交叉法 | 3,007 | 23 概念 × 名词表 × 33 句式 | 名词 → 该概念的答案 |
| S3 域外 | 2,268 | 168 个陌生名词（熊猫/区块链/摩天轮…）× 句式 | 抄名词 + 回避 |
| S4 无名词 | 472 | 数字/标点/重复字 | 没名词就不回声 |

合计 9,689 窗，核心答案池 **89 条**（23 概念 × ~3 + 20 句通用回避）。

### 关键设计：让句尾失去信息

33 个句式**在 168 个名词上交叉复用**，同一个结尾（"…是啥？"）出现在几十个
不同答案的样本里。模型再也无法用结尾查表，只能往中间看名词 —— 这是拆捷径，
不是加数据。

域外名词拿不到本概念的答案，只能落进通用回避池。
**"不懂"就是这样实现的：它不需要一条规则，它需要一条没有答案可给的路。**

## 3 规则怎么退场（带验收门槛）

原则：**先在语料里覆盖，再删规则**；一次只删一帧，删完跑
`coverage_zh_rules.py`（47 条用例）+ 板测，指标不掉才继续。

| 帧 | 现在管什么 | 退场条件 | 退场后靠什么 |
|---|---|---|---|
| `zh_identity` `zh_age` `zh_home` | 你是谁/几岁/住哪 | 回声命中 ≥80% 且身份类答案落池 ≥70% | 概念 `自我介绍` |
| `zh_nick` `zh_math` | ⑨ / 一加一 | 同上 | 概念 `⑨` `算数` |
| `zh_touch` `zh_affection` `zh_praise` `zh_insult` | 捏捏/喜欢你/夸/骂 | 域外组回声 ≥80% | 回声 + 回避池 |
| `zh_eat` `zh_trap` `zh_weird` `zh_spell` `zh_meta` | 怪问题 | 同上 | 回声 + 回避池 |
| `zh_emotion` `zh_happy` `zh_thanks` `zh_greet` `zh_bye` | 社交套话 | 同上前提 + 追问不失忆 | 概念 `打招呼` + S1 |
| `zh_listen` | 长句倾听 | 长输入不崩 | 语料里加 30~60 字输入 |
| `zh_friend*` `zh_capability` `zh_silly` | 关系/能力/装傻 | 落池率 ≥70% | 概念 `大妖精` `灵梦` `魔理沙` |

目标终局：**规则 0~3 帧**，只剩真·安全兜底（自伤/辱骂/纯符号）。
如果连那三条都能被 S4 覆盖，就是 0。

## 4 验收指标（不看 loss，不看 val）

1. **回声正确率**：回复开头 1~4 字 == 输入里的名词。这是"读了输入"的硬指标。
2. **域外未见名词**：训练里一次都没出现过的词（蜗牛/梅花/抽屉…），
   要求回声正确率不掉，且答案落在回避池。
3. **池归属率**：去掉回声后主体是否落在期望池（域内→概念 3 条；域外→20 条回避）。
4. **观感重复率**：连续 12 条不同输入的相邻同首字 / 同句率。
5. **不能只看整句命中**：89 条池子下整句命中会天然变低（同一个 prompt 有 3 种答法），
   这不是退化。

## 6 实测：三道配方，和那道墙（2026-10-21 下午）

三版语料，同一套 1800 步训练（5L/32E、block 128、LR 8e-4、从语言底座热启动）：

| 版本 | 语料差异 | A 域内新句式回声 | B 域外已见 | C 域外未见 | D 无名词 |
|---|---|---|---|---|---|
| react1 | 168 个固定域外名词，回声率 70% | 12/46 → 池 54% | 0/16 | 0/16 | 不回 ✓ |
| react2 | +4,199 条**随机伪名词**，70% | 13/46 → 池 50% | 0/16 | 0/16 | 不回 ✓ |
| react3 | 回声率 **100%**（有名必抄） | **32/46 (70%)** → 池 65% | 1/16 | 0/16 | 不回 ✓ |

react1→2 换了伪名词（理论上不可背，只能抄）没用；react2→3 把「哼，/哈，」这条
竞争路径掐掉，域内回声从 26% 跳到 70% —— 但域外仍然 0。

### 决定性测量：训练集里自己的样本，也抄不出来

拿 react3 在**它自己训练过的**伪名词样本上贪心解码，前 2 字命中 **0/16**：

```
U: 烛胶是啥？       语料: 烛胶？那是什…     贪心: 烛针啊，咱不知道…
U: 梯过是啥玩意？   语料: 梯过？那是啥…     贪心: 梯啊，咱不知道…
U: 蝴外波好看吗？   语料: 蝴外波嘛，咱…     贪心: 蝴独啊，咱不知道…
```

**首字常常对，次字必错。** 也就是说它学到的是「看开头一个字」，不是「把这段抄下来」。
A 组 70% 的"正确回声"也主要是查表（青蛙/雾之湖/灵梦都是背过的），不是复制。

伪名词不可能被背下来（每条只出现一次，4,199 条），所以这不是语料配比问题，
是**架构问题**：5 层 / **2 个注意力头** / 64 维 / ternary 权重，induction head 没长出来。
2 个头的预算大概只够一个"上一 token 头"，不够"匹配 + 复制两字"。

### 这道墙意味着什么

1. **"让模型复述对方的话"在本尺寸上封死。** 不是再训久一点、再换个配比能解决的。
2. 域外输入因此无法被"点名回应"，只能落进回避池。实测：约一半落池（「咱不知道，问这个干嘛！」
   这种），另一半跑成域内答案。比 canon4 的"100% 跑成域内答案"好，但没到"接住"。
3. 想真正做到零规则，只剩三条路（见第 7 节）。

## 7 结论修正：规则该退到什么位置

原来的设想是"模型接管一切"。实测把它切成两半之后，答案清楚了：

| 职责 | 归属 | 理由 |
|---|---|---|
| **话术**（说什么、什么口吻、什么态度） | **模型** | 89 条池子已覆盖 19 帧规则的全部话术空间，规则层引以为生的"回复库"已经没有存在必要 |
| **知识**（青蛙/⑨/灵梦/算数…） | **模型** | 23 个概念 × 3 条，实测落池 65% |
| **OOD 回避**（听不懂时说什么） | **模型** | 20 句回避池，实测域外 44~56% 落这一池，且不重复 |
| **路由**（这句里哪个词是"东西"） | **规则/固件** | 模型抄不出来，这是唯一原理性做不到的一步 |

所以"规则层干了大部分的活"这个感受，来源是**规则同时在干话术和路由**。
现在话术已经全部搬进权重，剩下的是几百字节的关键词表 + 一次前缀渲染 ——
那是"仅必需规模"。

三条可选路线（按性价比排）：

1. **回声挪到固件**（推荐，今天就能做）：固件取输入里最像名词的 2~4 字，
   拼成 `{词}？` 作为渲染前缀，模型的回复去掉开头语气词后接上。
   规则层归零，模型管全部文本。代价是回声不是"模型想出来的"，但用户看不出。
2. **加注意力头**（唯一可能解锁真复制的杠杆）：同参数量把 `n_head` 2→4
   （head_dim 32→16），从语言底座重训。要重跑预训练 + 人设，约 40 分钟。
   赌的是"2 个头不够、4 个头够长出 induction"——**没有证据，只是唯一没试过的变量**。
3. **接受现状**：模型管话术 + 概念 + 回避，规则只做路由。已经是"模型为主"。

## 5 风险（写在前面的，事后对账）

- **回声抄错位置**：可能抄成"怎么"而不是"青蛙"。指标 1 会直接暴露。
  → **实测更糟：抄不到 2 个字。** 见第 6 节。
- **回声 ≠ 理解**：用户可能觉得"你只会重复我说的话"。
  缓解：回声只占 70%，另 30% 用语气词开头；且回声后面紧跟的必须是**表态**。
  → 实测 70/30 会让首 token 信道被 7 个语气词堵死，必须 100% 回声。已改。
- **89 条太罐头**：如果回声带来的多样性不足以掩盖池子小，观感会退回"车轱辘"。
  缓解方案（按序）：每概念答案 3 → 5；加"同一答案 × 不同语气尾巴"的组合。
- **`⑨` 这类 1 字输入**：单 token 输入没有任何上下文，仍然最脆。这一格可能
  永远是规则的地盘 —— 这是"仅必需规模"里唯一我认可的一条。

## 8 规则退场审计（2026-10-21 夜，`board_rule_audit.py`）

工具：`:greedy + :rules 0`，逐帧抽 4 个关键词问模型，按「帧→概念归属」判定：
落进**对的**概念池 = 接管；落进别的概念 = 串味；域外帧落回避池 = 接管。
（第一版分类器把板端 `11 tok 127.7 ms/tok` 统计行算进回复，ASCII 占比过半
把中文全判成乱码 —— 修法：只取第一行。）

**退场（模型接管，话术进权重）**：

| 帧 | 证据 |
|---|---|
| `zh_nick` | ⑨/笨蛋/傻瓜 → 「不许…」3/4，1 条回避 |
| `zh_eat` | 吃大妖精→大妖精签名、烹饪琪露诺→回避、烤灵梦/咬魔理沙→各自签名 4/4 |
| `zh_weird` | 世界末日/外星人 → 「没听说过，问这个干嘛」3/4 |

**保留（模型给错池答案，读起来接不住）**：`zh_praise`（好厉害→「谁说小了」）、
`zh_touch`（抱抱→「第一？」）、`zh_happy`、`zh_home`、`zh_friend`（谁更→「逗你」）、
`zh_math`（1+1→「2」，直接破坏人设）。社交兜底（identity/thanks/greet/bye/
listen/capability/emotion）也留：模型对这些要么串味要么回避，规则的罐头句
（「谁惹你了？咱去冻住他！」）比「没听过，咱只管冰和青蛙」更入戏。

退场后：**24 帧/218 词/104 回复 → 21 帧/185 词/89 回复**，Flash 94.0%→93.9%。
端到端复验：⑨/吃大妖精/世界末日走模型且全入戏，hi/你是谁/谢谢/一加一/好厉害/
抱抱照常走规则，你好矮仍归模型（负关键词生效）。
`coverage_zh_rules.py` 60/60 通过（两条长怪问题改判 `zh_listen` 兜底帧）。

**下一步的候选**（都还没做）：`zh_identity`/`zh_age` 模型已能答「你谁」「几岁」
（「冰之妖精，雾之湖的老大」），但「你是谁」会串到最强 —— 要么补语料要么留规则；
OOD 回避率 62~79%，残余失败（天平→「来啦」）靠固件回声兜底；
语料小 bug：`再见` 在 `打招呼` 的问法里但答案是问候式（「来啦」），bye 帧因此保留。

## 9 言语行为概念化（2026-10-21 晚，stance5）

截图两例答非所问，根因同一个：**言语行为在概念表里没有落地槽**。
23 个概念全是名词性话题（青蛙/灵梦/红魔馆…），而「挑衅」「比较」是行为——
模型只能抓输入里唯一的名词（让灵梦收拾你→灵梦），规则层只有关键词 AND、
同样不懂行为（灵梦和大妖精谁厉害→zh_friend_dyj 回了句找人的）。

**修复 = 把言语行为变成概念**（零新增规则帧，反而给规则开了口子）：

| 新概念 | 签名 | 问法样例 |
|---|---|---|
| 被挑衅 | 让她来 | 让灵梦收拾你 / 你等着 / 看我不叫大妖精来 |
| 比试 | 她俩 | 灵梦和大妖精谁厉害 / 她俩谁强 / 巫女和黑白谁厉害 |

配套：`check_lexicon.py` 落盘（五条硬约束全自动，当场抓到签名不齐+字表外字）；
「再见」移出打招呼问法（语料 bug，答案本是问候式）；规则给 zh_friend /
zh_friend_dyj / zh_listen 加 _CMP_NO 除外词（实体名+和、她俩）放行给模型。

结果（PC 探针，同参数 5L/32E）：seen 89%（88）· unseen 64%（61）· OOD 86%（79）。
截图两句均修复，附带修好两个老漏（大妖精是谁、你厉害吗）。残留：她俩谁强→魔理沙
（无实体名的比较仍会掉到实体概念，下一步可给比试补 2~3 条无实体问法）。

**方法论沉淀：遇到"答非所问"先问"这个言语行为有没有概念槽"，**
而不是先加规则或加参数——加规则是拿罐头句堵，加参数是拿容量赌，
都不如把缺的那类行为补成语料（每概念 6 问法×4 答案，边际成本≈0）。

## 10 垃圾输入崩坏修复（2026-10-21 深夜，两条路线取一）

用户截图：`aabbccddee` 连问 4 次，答案在 4 个池子间乱跳，其中一次语言崩坏
（「结实不是总担心咱？其冻冻的第二个！」）；`lorem ipsum` 前半入戏后半崩坏。

**根因**：词表 ASCII 只有 27 个（`User:Bot"',!?1hlp2icFgma9`），字母串/数字串/
英文句进模型就是 UNK 序列；语料里从没有「UNK 序列 → 回避」的样本
（S3/S5 是 OOD名词×中文问句，S4 是中文语气词）。贪心时 DEFLECT 勉强第一，
temp 0.7 一扰就串池。附带 bug：「在吗」同属打招呼问法和 S4 噪声，自己打自己脸。

**路线A（模型侧，stance6，不烧录）**：新增 S6 垃圾形态族 150 条
（`gen_stance_corpus.py --n-junk`，故意不滤字表——UNK 是真实分布）。
temp 0.7 采样 **48/48 全回避**（stance4/5 是几乎全串味+崩坏），
但 seen 89→83 / unseen 64→57 / 挑衅 5/5→2/5。**6~7 个路由点换 OOD，不值。**

**路线B（固件侧，zh_junk 帧，已采用）**：关键词帧全落空 + 输入无一个非 ASCII
字节 → 直接抽 DEFLECT 池（`kZhJunkRep` 由 `gen_rules_cpp.py` 从

成本 376 B。「是不是中文」是元信息，规则层 3 行搞定，模型原理上难学。
`hi`/`hello` 仍归 greet 帧（规则先跑）；「abc你好」含中文走模型。

先问"X 是不是模型原理上判不了的"——元信息归规则，语义归模型，别拿容量赌。

## 11 「她」字签名污染 + temp 定档（2026-10-21 收尾）

板上 temp 0.7 实测暴露：`她俩谁强` 0/6 稳定串味。根因不是训练量，是**签名设计**：
比试=她俩 / 妖精同伴=她们 / 魔理沙=她那 / 大妖精=她是——四概念共享首字「她」且第二字
近义，2.17M 模型分不开。stance7 换签名后同样 0/6（串「说起」）：共享首字就串，
与训练随机性无关，是结构问题。

修复：只留大妖精用「她」，比试=**两个** / 妖精同伴=**一起** / 魔理沙=**说起**。
`check_lexicon.py` 加⑥（签名共享首字 = 警告，不断阻断——「说」组冻/起差异大可接受）。
新签名词典已落，stance7（同语料重训）greedy seen 85%/unseen 59%，temp 0.7 言语行为
反而比 stance5 差——2.17M 的言语行为路由在"勉强学会"边缘，重训=重新抽签。
**签名修词典留给未来，模型仍烧 stance5。**

**temp 默认 0.7 → 0.5**（`_temp_sweep.py` 板上 9 输入×6 次×3 温度）：
0.7→70% / 0.6→69% / **0.5→80%**。签名路由的本质是首 2 字的概率差，温度一高分布
拉平、第二名翻上来。旧结论（0.85→0.7 为完成率/OOV）是故事时代+无签名制的，作废。

**legacy-sig 快照**：词典改签名后，旧模型答案会被新签名判串味——
probe_stance stance5 无快照 79% vs 有快照 89%（10 个百分点假差距）。
`model/stance5_legacy_answers.json`，两个探针均支持 `--legacy-sig`。
**模型与词典必须版本绑定。**

板上最终态：stance5 + zh_junk + temp 0.5 + 21 规则帧，RAM 92.0% / Flash 94.0%。

## 12 问句类型矩阵：为什么补漏不是长久之计（2026-10-21 深夜）

用户截图 5 例：「你打得过灵梦吗/你打得过大妖精吗」被 zh_friend 截走、
「你喜欢灵梦吗」被 zh_affection 截走、「你吃什么」→「冰之妖精琪露诺」、
「你在干嘛」→「来啦来啦」。用户问：事后补漏重训不是长久之计，有更好的方法吗？

**诊断（PC 探针 :rules 0，temp 0.5）**：三个系统性失败模式，不是零星漏题——
1. 无实体"你X"状态问句（吃什么/在干嘛/饿不饿/要去哪/想什么）→ 全塌到自我介绍
2. 态度问句（喜欢X/讨厌X/想要X）→ 全塌到喜好
3. 能力问句（打得过X）模型其实能答（「第一，不服就来打一场！」），
   但被 zh_friend 帧截走，用户看不到

**根因（组织方式错位）**：语料按"话题轴"组织（28 个名词概念），用户输入按
"问句类型"组织——同一名词能被十几类问句问，每类答案结构不同。
话题×手写问法的覆盖是 O(概念×想象力)，永远补不完；**问句类型有限可枚举**
（中文日常问句约 15 类：态度/能力/时态/情态/认识/经验/处置/属性/状态…）。

**解法 = 两个有限工程（本次 stance8）**：

1. **深度（正空间）**：补高频概念槽。新增日常生活三概念（吃饭=吃冰/睡觉=睡在/
   玩耍=玩起，各 6 问法×4 答案）。注意名词表不能含动词（吃/睡/玩）——
   answerable() 会把「你吃什么？吃冰！」这种**接龙**误判成前缀结巴。
2. **广度（负空间，S7 元行为族）**：`META_TMPL` 33 个带槽模板 + 15 个无实体模板
   × 名词池（概念名词+OOD+其他角色）≈ 2500 组合，**排除已配置概念槽的**，
   其余 450 条统一 -> DEFLECT。模型从此对陌生形态的默认行为是
   「没听说过，问这个干嘛」（入戏回避），而不是塌到随机概念。
   负空间模板不需要人味（通顺+可学即可），正空间才需要——react4 教训的边界：
   机械交叉的问题在"答案随机"，这里答案统一是 DEFLECT，不犯那个错。

**配套**：zh_friend / zh_friend_dyj 加能力比较除外词（打得过/谁强/谁厉害/
谁更/怕不怕），能力问句退场给模型；信息问句（你和X认识吗）模型没学过，留规则。
zh_affection 保留（规则的「喜欢？咱谁都不喜欢……除了冰。」比模型的
「七回打完」更切题）。

**这个方案为什么是长久之计**：以后出现新的日常话题，不需要"发现漏→补概念→
重训"——问句类型库是一次性有限工程，新话题只是换名词，而名词泛化由
S3/S5（OOD名词）+S7（类型×名词负空间）已经教会。模型的默认行为从
"乱串"变成"谨慎回避"，崩坏感消除不依赖穷举话题。

## 13 三层分工定稿（2026-10-22，stance26 + 上板验收）

### 13.1 一个反例划出了边界

上一节第 1 条「深度」已经落地（日常三概念进模型、问法 6→22 条），但同时暴露出
一条比"补漏"更根本的规律。板上实测（`_per_concept.py`，PC 侧 fp32 贪心）：

| 模型 | 总分 | 吃饭/睡觉/玩耍 | 被挑衅/比试/恶作剧 |
|---|---|---|---|
| stance5（25 概念） | — | 0/6 · 0/6 · 0/6 | 6/6 · 4/6 · 6/6 |
| stance9（28 概念） | 77% | 3/5/4 | **1/6 · 1/6 · 1/6** |
| stance10（28 概念） | 72% | 2/3/2 | **2/6 · 0/6 · 2/6** |

现象：**概念数从 25 涨到 28，被挑衅/比试这两个"言语行为"概念整类塌掉**，
而它们原本是 6/6、4/6。

追问下去，模型给出的答案是**名词的答案**，不是言语行为的答案：

```
「让灵梦收拾你」   -> 灵梦的答复（第一的位置，谁来都抢不走）
「让魔理沙打你」   -> 魔理沙的答复（那个黑白，不服就来）
```

**它不是"没学会"，是按名词路由。** 2 头 / 64 维 / ternary 的 QK 电路只能匹配
"句子里出现了哪个名词"，匹配不到"有人放话要收拾咱"这种句法信号。
—— 这条与第 6 节"抄不动"同源：都是注意力电路的能力下界，不是配比问题。

### 13.2 划界：谁管什么，按信号形态分

| 层 | 管什么 | 判据 | 例子 |
|---|---|---|---|
| **模型** | 话题概念 | 信号是**一个名词** | 青蛙/冰/湖/大妖精/吃饭/睡觉/玩耍 |
| **规则** | 言语行为 | 信号在**句法**里，没有专属名词 | 威胁 `zh_taunt`、第三方比较 `zh_duel`、问候、告别 |
| **固件** | 元信息 | 与语义无关 | `zh_junk` 垃圾拦截、sig-stuck 防背稿、echo 回声 |

按这条线重划后，动作是：

- `被挑衅` / `比试` **从模型彻底删除**（`stance_lexicon.ANSWERS`/`QUESTIONS`、
  `gen_react_corpus.CONCEPTS` 三处同步），签名表 28 → 26；
- 新增规则帧 `zh_taunt`（收拾/教训/打你/我叫人/你等着…）与 `zh_duel`
  （子句1 和/跟/与/俩 + 子句2 谁）；
- **`zh_duel` 必须带除外词 你/咱/比**：自比问句（你打得过灵梦吗 / 你俩谁强 /
  和灵梦比谁强）是 最强/灵梦/魔理沙 的训练问法，规则抢走就是纯损失；
- 日常三概念问法 6 → 22 条（吃饭 22 / 睡觉 22 / 玩耍 22）。

### 13.3 stance26 重训

`dataset_mix_stance26.txt` 7019 窗（stance5 是 7057）。配方**四个参数缺一即废**：

```
ESPGPT_CHAT_WEIGHT=10   ESPGPT_WARMUP_ITERS=50
ESPGPT_T_MAX=1500       ESPGPT_BATCH_SIZE=128
```

train 1.8757 / val 3.0334，量化 1163.4 KB。per-concept **191/203 = 94%**
（203 = 26 概念问法总数）：

| 分组 | 结果 |
|---|---|
| 吃饭 / 睡觉 / 玩耍 | 17/22 · 22/22 · 22/22 |
| 23 个共用概念 | 90% → **95%**（恶作剧/冰/夏天等全部恢复 6/6） |

顺带把"规则抢话"压到历史最低：全量 203 条训练问法里规则只接走 **7 条（3%）**，
原为 35/167（21%）；两个新帧偷走训练问法 **0 条**；`coverage_zh_rules.py` 60/60。

> 教训（第二次踩）：**val loss 相近 ≠ 行为相近**。v2 val 2.96 但 per-concept 73%，
> v3 val 3.03 却是 94%。判行为只认 per-concept 探针，不认 loss。

### 13.4 板上第一轮失败：防背稿与贪心互斥

重烧后板上 A 段（`:greedy` / `:rules 0`）只有 **吃饭 11/22 · 睡觉 5/22 · 玩耍 6/22**，
而 PC 侧同权重是 22/22 —— 说明问题不在权重。

日志里全是 `回避 + intent:sig_stuck`。根因：**一个概念只有 4 条表态**，贪心连问
5 句必然复读；撞环后固件重掷，但 `:greedy` 下不提温 = **逐字节相同的重抽**，
必然二次撞环 → 从第 4 句起全转回避池。

修复：`main.cpp` 两处检测点都加 `temp_save > 0.0f`，即 **`:greedy`（temp<=0）
整体关闭 sig-stuck**。理由：回归探针依赖确定性，采样防背稿本来就不该掺进来。

### 13.5 最终验收（`_probe_26.py`，重烧后）

| 段 | 内容 | 结果 |
|---|---|---|
| A | 吃饭 / 睡觉 / 玩耍（`:greedy` `:rules 0`） | **17/22 · 22/22 · 22/22 = 61/66（92%）** |
| A | `stuck` 计数 | **0** |
| B | 12 条言语行为（`:rules 1`） | 规则帧 **12/12** |

"模型不行"和"固件干扰"才能彻底分开。修复前那 5/22、6/22 就是固件造出来的假象。
