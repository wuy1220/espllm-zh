# 架构扩容的明确结论，以及那 3 MB flash 到底能不能用

两个都是实测数，不是推算。前一个问题用训练好的检查点在固定验证集上重测，
后一个问题在板子上跑了一个独立的探测固件（`bench_fs/`）。

---

## 一、扩容：加层比加专家划算，代价只有 7%

### 为什么不能看训练日志

`ab_A/B/C.log` 里的 val 是 `eval_iters=10` 算的，噪声约 **±0.05**，而三个臂之间的
差距是 0.04–0.12 —— 同量级。实测过一次：A 在最后 3500 步里 val 从 2.8788 涨到
3.0147，那不是发散，是换了验证批次。

所以用 `eval_arch_ab.py`：固定 100 批 × 32 序列 × 64 token，所有臂跑同一个
forward（BitLinear 的假三值量化在 forward 里生效，和训练一致），纯 CE，
不含 label smoothing 和 MoE aux loss。

### 结果（`dataset_mixed2`，block 64，25000 步，同种子同 schedule，全部从头训）

| 臂 | 参数 | Flash | 验证 CE | 困惑度 | 相对 A | 每 token 流量 |
|---|---|---|---|---|---|---|
| **A 4L/20E**（现役） | 1.17M | 68.0% | 2.1740 | 8.79 | — | 159,392 B |
| **B 5L/32E** | 2.17M | 90.9% | **2.0572** | **7.82** | **−0.1167** | 170,432 B (1.07×) |
| **C 4L/40E** | 2.16M | 90.6% | 2.0976 | 8.15 | −0.0763 | 164,672 B (1.03×) |
| mixed3（12k 热启动，跨语料对照） | 1.17M | 68.0% | 2.2426 | 9.42 | +0.0687 | — |

B 和 C 的参数量差 0.5%、Flash 差 0.3%，唯一变量就是预算花在哪。

### 三个结论

**1. 扩容明确有效。** 两个臂都比 A 好，差距是噪声的 2 倍以上。

**2. 同样预算，深度比专家数多赚 0.040 nats（约 1.7 倍效率）。**
B 比 C 好 0.040 nats，而参数几乎一样。
注意训练日志给出的印象是反的：那里 C≈A（2.8808 vs 2.8788）、B 好 0.086。
**如果只看日志，会得出"40 个专家完全没用"的错误结论** —— 实际是 −0.076。

**3. 代价只有 +7% 每 token 流量。**
`tok_emb` 的 128 KB 与层数无关、且占流量大头，所以加层的摊薄效应很强：
4 层 159 KB → 5 层 170 KB。按板上实测 85 ms/token 算，约 **91 ms/token**，
单条回复（24–29 token）多 0.15–0.2 秒。

**−11% 困惑度换 +7% 延迟**，在"质量优先"下这个交换是明确该做的。

### 还没测的空白

**6L/20E**（1.69M、79.9%、流量 1.09×、余量 210 KB）没跑过。它比 B 少 0.48M 参数、
多 115 KB 余量，按 5L/32E 的规律很可能接近 B 的质量。

**下一步应该在 `dataset_mixed4`（block 128、新 chat 语料）上比 6L/20E vs 5L/32E**，
而不是直接拿 block 64 的绝对值去改线上模型 —— 语料和窗口都变了，绝对 CE 不可比，
但排序大概率成立。

## 二、那 3 MB：不是"没计入"，是当前 ldscript 根本没开

### 为什么代码区只能是 1 MB

ESP8266 把 SPI flash 映射进 CPU 地址空间，`irom0_0_seg` 从 **0x40201010** 开始，
到 **0x40300000** 就是地址空间的尽头。这一段是 **0xfeff0 = 1,044,464 B（1019 KB）**。
`static const ... PROGMEM` 必须落在这里才能被按指针访问，**换任何 ldscript 都不会变大**。

### 但 3 MB 是可用的，只是没开

```
eagle.flash.4m.ld                        eagle.flash.4m3m.ld
  sketch @0x40200000  1019 KB              sketch @0x40200000  1019 KB
  empty  @0x402FEFF0  3056 KB   ← 浪费      empty  @0x402FEFF0     4 KB
  spiffs @0x405FB000     0 KB              spiffs @0x40300000  3048 KB
  eeprom @0x405FB000     4 KB              eeprom @0x405FB000     4 KB
```

两个脚本的 `irom0_0_seg`、EEPROM、rfcal、wifi 偏移**完全相同**，差别只有
`_FS_start/_FS_end`。所以切换是零风险的 —— 已实测：

```
切换前  Flash 761,359 B (72.9%)   RAM 73,912 B (90.2%)
切换后  Flash 761,359 B (72.9%)   RAM 73,912 B (90.2%)   ← 逐字节相同
```

`platformio.ini` 已改为 `eagle.flash.4m3m.ld`，固件已烧录并验证启动正常
（arena 39456/40960、ctx 104、free heap 6552）。旧配置留在 `platformio.ini.bak-4m`。

### 板子上实测：读一次专家权重多少钱

`bench_fs/` 是独立工程（主固件 RAM 已 90%，这个探测要 32 KB 缓冲 + 384 KB 测试文件）。
4 MB 芯片实测 `Manufacturer 5e / Device 4016`，挂载后 **fs total = 3,121,152 B**。

1.6 KB = 一个专家的权重（3 个 64×64 ternary + scale）。同板、同频、同缓冲：

| 读法 | 1.6 KB 随机读 | 4 KB 随机读 | 有效带宽 |
|---|---|---|---|
| mmap `pgm_read_dword`（现役） | **112.0 µs** | 273.9 µs | 14.3–15.0 MB/s |
| 裸 `ESP.flashRead` | 197.6 µs | 496.9 µs | 8.1–8.2 MB/s |
| LittleFS 常驻句柄 seek+read | **435.0 µs** | 991.2 µs | 3.7–4.1 MB/s |
| LittleFS 每次 open/seek/read/close | 782.9 µs | — | 2.0 MB/s |

顺序读 4.5 MB/s，写 **54 KB/s**（3 MB 写满约 58 秒）。

**整 token 模拟**（每层拉一个路由专家的权重，句柄常驻）：

```
4 层 × 1.6 KB  ->  1.74 ms/token   (+2.0% of 85 ms)
6 层 × 1.6 KB  ->  2.61 ms/token   (+3.1%)
```

### 结论：3 MB 能用，而且很便宜

把**专家权重**放进文件系统、共享权重（tok_emb + attention）留在 mmap：

- 增量成本 = FS 读 − mmap 读 ≈ 1.74 − 0.45 = **+1.3 ms/token（1.5%）**
- 容量从 44 专家上限涨到 **约 258 个**（3,121,152 ÷ 11,520 B/专家，扣 4.5% FS 开销）
- 每 token 仍只读 1 个专家，**所以延迟不随专家数增长**

如果不想付文件系统的开销，可以直接把权重 bin 烧到 `0x300000`，
用 `ESP.flashRead` 裸读，**快 2.2 倍**（198 vs 435 µs），代价是自己在
`extra_scripts` 里管烧录偏移、没有文件系统帮你管布局。

### 但"能用"不等于"现在就该用"

1 MB 之内还没用完：**8L/20E 是 91.7%**（625 KB 权重 + 332 KB 代码，装得下）。
按已测的"深度 > 专家"规律，先把预算花在 8 层上比堆专家更值。

3 MB 的真正价值按优先级：

1. **支撑 10–12 层**。10L/20E = 103.5%，只在 1 MB 里差 37 KB；把 2 层放 FS 就装下了。
   流量 1.27×（约 108 ms/token），而 FS 的额外开销只有 +2% 左右。
   这是深度路线唯一能继续走的方式。
2. **存多套权重**（chat / story / A/B 对比），换模型不用重烧 765 KB 固件。
3. **OTA 更新权重**：400 KB 权重写盘约 7 秒，比烧整份固件快得多。
4. 专家数堆到 200+ —— 有效，但边际收益已知在递减（20→40 只有 0.076 nats）。

## 复现方式

```bash
# 架构对比（55 秒，读三个已有检查点）
cd espllm && THREADS=6 python eval_arch_ab.py

# 容量/流量预算
python arch_ab.py

# 板上 flash 探测（会格式化 0x300000 之后的 3 MB，不影响代码区）
cd espllm/bench_fs && pio run -e benchfs -t upload
python capture.py COM5 60
```

注意 `bench_fs` 会覆写板上的主固件，跑完要 `pio run -e esp8266 -t upload` 烧回来。
