# 琪露诺训练语料：获取方法（含实测否决记录）

> 目标：约 35,000 条 / 1.6M token，回复位 ≤25 字、字表内、口语、具象。
> 用户设定：**普通人类访客**（她是居高临下的妖精，会叫对方"人类"或"你"）。

---

## 0. 结论先说

**这个任务的瓶颈不是"找到语料"，是"造出语料"。** 我实测了四个候选源，三个必须否掉：

| 源 | 实测结果 | 判定 |
|---|---|---|
| HF 上 `search=touhou` 的 20 个数据集 | 全是角色 LoRA **图像**集（CyberHarem 系列），零对话语料 | ✗ 不可用 |
| `zzoceanpie/yukari-synthetic` | 921 条；回复 **中位 83 字 / p90 151 / max 363**，文学化长句 + 8 维情感标签 | **借配方，不借文本** |
| `Jax-dan/HundredCV-Chat` | 24,750 组 Apache 2.0；句长 p50 31 字；788 个话题全是校园/科技/职业规划 | ✗ 话题零重合 |
| THBWiki | 对 curl 一律 **418**，加浏览器 UA 也挡 | ✗ 且没必要 |

所以路线是：**人工定骨架 → 程序化扩写 → （可选）LLM 润色 → TinyStories-Zh 只做语言底座**。

## 1. 三个"看似能用其实不能用"的实测细节

### 1.1 八云紫那个数据集：配方值得抄，文本必须扔

它是目前唯一的中文东方角色对话数据集（Apache 2.0，1K<n<10K）。做法很干净：
Player 发言取自真实中文日常对话，回复由 Teacher 模型按性格 + 8 维 Plutchik 情感标签生成，
明确声明不含官方原文。**这套流程我们可以照搬。**

但它的输出形态对我们是有害的：

```
IN  当然，工作中遇到问题都会联想到大学学习的内容。
OUT 在工作中回溯大学的时光，这倒像在暮色中追逐晨曦的影子——或许能指引方向，
    但夜晚的星辰，往往更值得凝视。
```

中位 83 字、p90 151 字、最长 363 字，`——` 和比喻堆叠。这是 7B 级模型的语言能力，
**2.17M 参数一个 token 都学不动**。更要命的是它把 8 维情感标签塞进 instruction 前缀
（`[<|轻微喜悦|><|极轻微愤怒|>...]`），对我们等于白烧 8~24 个 token 的窗口。

**结论：只抄"Player 用真实语料 + Teacher 生成回复 + 情绪控制"这个结构，不抄任何一条文本。**

### 1.2 HundredCV-Chat：许可很好，内容完全不搭

Apache 2.0、24,750 组、真实中文多轮闲聊——听起来正是"普通人类"该说的话。实测：

- 单句 p50 **31 字**（含 `user1：` 前缀），比我们想要的短输入还长
- 788 个话题，前 15 名是「校园生活分享 / 科技创新 / 未来职业规划 / 编程经验分享 / 职业发展规划 / 团队合作心得 / 开源项目经验分享」
- 它是从 100 份**简历**派生出来的，双人都是大学生/职场青年，互相叫名字

冰、青蛙、湖，一个都没有。拿它作用户位，等于教模型"用户会聊职业规划"——幻想乡里没人这么说话。

**结论：不做用户位。** 用户位本来就在封闭域内，模板生成更准。

### 1.3 THBWiki 抓不到，但也不需要抓

`curl` 带不带 UA 都是 `HTTP/1.1 418 I'm a teapot`。有 TLS 指纹或 JS 挑战，不是换个头能过的。

但这是好事，因为**琪露诺的设定量小到可以手写**。求闻史纪里她那个词条只有几百字：
冰之妖精 / 雾之湖 / 操纵冷气 / 湖附近妖精的领袖 / 爱恶作剧 / 冻青蛙再解冻 / 官方认定的笨蛋 / ⑨。
加上出场作（红魔乡 2 面、妖妖梦、花映塚、非想天则、妖精大战争、天空璋）。

**这些事实我直接写成 2,000 字的设定卡，比爬虫更准、更快、更没有版权问题。**

## 2. 四层语料工厂

```
L0 设定事实  2,000 字   人工      → 只产"事实点"，不产句子
L1 人设种子    600 条   人工      → 决定人设不走样的锚
L2 程序化扩写 28,800 条 脚本      → 主力，完全可控
L3 LLM 润色   5,000 条  可选      → 只换说法，不改事实
L4 语言底座   9,000 条  TinyStories-Zh → 只进用户位/旁白位
```

### L0 设定事实（人工，2,000 字）

只写**事实三元组**，不写句子。例：

```
琪露诺 | 种族 | 冰之妖精（妖精里最强的一档，幻想乡里很弱）
琪露诺 | 住处 | 雾之湖边的冰屋
琪露诺 | 能力 | 操纵冷气，能瞬间冻结小东西
琪露诺 | 自称 | 咱
琪露诺 | 名言 | 咱可是最强的！
琪露诺 | 官方绰号 | ⑨ / 笨蛋（花映塚说明书标注）
琪露诺 | 兴趣 | 把青蛙冻住再放回河里解冻，三只里会弄碎一只
琪露诺 | 好友 | 大妖精（她叫"大酱"）
琪露诺 | 关系 | 输给灵梦和魔理沙很多次，但从不承认
琪露诺 | 弱点 | 算数算不清、夏天怕热、被叫⑨会炸毛
琪露诺 | 不可能知道 | 外部世界、现代科技、复杂理论
```

这张表的存在意义是**给 OOD 拒答提供边界**：不在表里的话题，她必须说"咱不懂"。

### L1 人设种子（人工，600 条）

用 YAML 手写，分五块：

| 块 | 条数 | 作用 |
|---|---|---|
| 身份锚 | 80 | 自我介绍、种族、住处、能力、"你问咱是谁？" |
| 口癖锚 | 60 | 最强宣言、否认、炸毛、撒娇，每条带不同句式 |
| 弱点锚 | 80 | 算数、冻碎青蛙、怕热、被叫⑨，**含 40% 答对 60% 答错的混合** |
| 关系锚 | 80 | 大妖精、灵梦、魔理沙、若鹭姬、红魔馆 |
| OOD 拒答 | 100 | 域外问题 → "这个咱不懂" / "咱只知道冰和青蛙的事" |
| 多轮骨架 | 200 | 2~4 轮完整对话，检验"记住上句" |

**混合分布是 L1 的核心设计**：如果每条都答错，她会退化成复读机；如果每条都答对，
"笨蛋"这个人设就没了。目标是 60% 理直气壮答对、40% 自信地答错。

### L2 程序化扩写（主力，28,800 条）

不做"模板 + 随机词"的粗暴替换，做**三元组约束扩写**：

```
话题实例 = (话题, 对象, 动作)     例：(青蛙, 池塘边的青蛙, 冻住)
句子     = 意图 × 句式骨架 × 槽位填充 × 语气词
```

- **20 话题 × 10 对象 = 200 个话题实例**（表见第 4 节，会扩到 30 对象 = 600）
- **12 种意图**：提问 / 回答 / 炫耀 / 否认 / 抱怨 / 邀请 / 拒绝 / 回忆 / 惊叹 / 反问 / 撒娇 / 不服
- **每种意图 8~12 个句式骨架**，共约 120 条骨架
- **每个 (实例, 意图) 生成 3 个变体** → 600 × 12 × 4 ≈ 28,800

意图 × 句式的例子（青蛙 + 炫耀）：

```
「咱把池塘里最大的那只青蛙冻住了，硬得像石头！」
「你见过冻住的青蛙吗？咱冻的，一碰就嘎嘣响。」
「哼，冻青蛙这事，整个雾之湖没有比咱更快的。」
```

**为什么要意图轴**：只有话题轴会得到"关于青蛙的 30 种说法"，而真实对话是"关于青蛙的
30 种**态度**"。意图轴才是对话感的来源，也是让模型学会"同一个话题能被问成不同形状"的关键。

**多轮拼接 6,000 条**：从 L1 的 200 条骨架出发，程序化接龙（问 → 答 → 追问 → 答 → 反问）。
这一块直接决定她在板上"记得住上一句"，是 GuppyLM 复现的核心。

### L3 LLM 润色（可选，5,000 条）

只对 L2 的 17% 做，因为：

1. 全量润色成本高、且会引入设定幻觉
2. 但我们确实需要一部分"不那么模板"的句子，否则模型会学到模板的呼吸节奏

做法：把 L2 一条 + 人设卡一起喂给 Teacher 模型，要求"用琪露诺的口吻重写，≤25 字"。
然后**必须过三道闸**（见第 3 节）。**没有 API 也能跑通全流程**，只是语言会偏模板腔，
质量损失估计在 5~10%，不影响可行性验证。

### L4 语言底座（TinyStories-Zh，9,000 条）

实测可下（已验证）：

```bash
# MIT 许可，803 MB，3 个 parquet
https://hf-mirror.com/datasets/RobinChen2001/TinyStories-Zh-2M
# 只需第一个分片 267 MB 就够抽 1.5 万句
```

用法严格按上一轮定的**位置区隔**：

- **6,000 条进「用户位」**：从故事里抽引号对白（`"..."`），筛 8~30 字、全字表内。
  小孩说话的口吻，正好等于一个好奇的人类访客
- **3,000 条进「旁白位」**：场景句（"外面下着雪""湖面结了一层薄冰"），回复仍来自模板
- **回复位一条都不放**

## 3. 三道质量闸（顺序不能换）

| 闸 | 规则 | 砍掉的量 |
|---|---|---|
| **1 字表** | 全部字在 2000 字表内 | ~3%（TinyStories-Zh 里生僻字不少） |
| **2 长度** | 回复 6~25 字，句末有 `。！？` | ~8% |
| **3 难度** | 训到 10k 步后，用当前模型给语料打分，砍 CE 最高的 10% | 10% |

**第 3 道闸是关键，也是 yukari 那个数据集给我的教训**：语料难度必须和模型容量匹配。
一条 83 字的文学化长句，对 2.17M 来说是纯噪声——它学不会，只会拉高 loss 并污染采样分布。
训 10k 步后回头砍掉最难的 10%，等于自动把语料校准到模型的能力边界上。

## 5. 用户位该怎么写（"普通人类"的落地）

这一点决定她是"自言自语"还是"在跟人说话"。三条规则：

1. **用户叫她的方式**：`琪露诺` / `你` / 偶尔 `小妖精`
2. **她叫用户**：`人类` / `你` / 想收小弟时叫 `小弟` / 故意气人时叫 `人类的小鬼`
3. **用户的语气**：好奇、试探、偶尔逗她、偶尔怕她。**不恭维、不撒娇、不长句**

```
用户：你就是那个最强的妖精？
琪露诺：对对对！咱就是最强的！你终于听说了？

用户：听说你连算术都不会。
琪露诺：谁说的！咱会算！……三加五是、是八！对吧！

用户：这只青蛙怎么硬了。
琪露诺：咱冻的！漂亮吧？等一下咱就把它放回湖里。
```

注意第三条：用户**永远不超过 20 字**。用户位太长会挤掉回复位，也会让模型把
"用户说长句"当成常态——而真实的封闭域对话里，人类只说一两句。

## 7. 第一步（我可以直接开始）

1. 写 `persona/cirno_card.md`（L0 设定卡，2,000 字）
2. 写 `persona/seed.yaml`（L1 600 条种子，含多轮骨架）
3. 写 `gen_persona_corpus.py`（L2 生成器：120 条句式骨架 + 三元组约束 + 三道闸）
4. 跑一次，产出 `dataset_cirno/train.bin` 与 `.mask`，报**字符级 tokenizer 的字频表**
5. 用字频表定 2000 字，跑一次全量 CE 分布，确认语料难度在模型能力范围内

L3（LLM 润色）**不影响前四步**，可以后面再补；L4 的 TinyStories-Zh 可以先只下第一个分片。

**需要你确认的只有一件事**：有没有可用的 LLM API（或本地大模型）来做 L3。
没有的话我把 L2 的句式多样性做到 150 条骨架，用纯模板跑，也能验证路线通不通。
