# 中文角色 chatbot：东方 Project 人设候选评估

> 目标不是"会聊天的助手"，是 **GuppyLM 式封闭域角色**：人设烤进权重、无 system prompt、
> 话题封闭、回复 20~25 字。约束：2.17M 参数（激活 0.26M）、2048 词表（2000 汉字 + 48 控制）、
> 字符级分词、32 窗口。

---

## 一、判据：为什么"这个角色好训"和"这个角色好玩"是两件事

2.17M 参数装不下"人格"，只能装下**一组可被触发的标记**。所以选角色要按下面 6 条打分，
而不是按人气。

| # | 判据 | 为什么它决定成败 |
|---|---|---|
| 1 | **口癖可编码** | 模型要能用 1~2 个 token 就"跳进角色"。自称（咱 / 本小姐）、句末语气词、固定台词。没有这个，角色只是"一个会说话的模型" |
| 2 | **句长友好** | 2M 参数写不了复合句。角色本身说话短 = 语料天然短 = 训练分布与推理预算一致 |
| 3 | **话题封闭度** | 能否枚举出 18~20 个话题、每个话题 30 个对象。职域型（冰湖 / 图书馆 / 红魔馆）好；"什么异变都管"的角色封闭不住 |
| 4 | **词汇高频度** | 2000 汉字词表下，**具象词**（冰、青蛙、湖）远比**抽象词**（命运、威严、七曜）安全。抽象词一旦不在词表，就退化成碎片 |
| 5 | **对话抓手** | 角色必须有"可被调戏的弱点"，用户才会主动说话、对话才能持续多轮。没有抓手 = 聊两句就冷场 |
| 6 | **语域与 TinyStories-Zh 重合度** | 我们要掺 TinyStories-Zh 做语言底座。角色语域越接近儿童故事，掺入造成的分布冲突越小 |

### 打分（5 分制）

| 角色 | 口癖可编码 | 句长友好 | 话题封闭 | 词汇高频 | 对话抓手 | 语域重合 | 合计 |
|---|---|---|---|---|---|---|---|
| **琪露诺** | 5 | 5 | 5 | 5 | 5 | **5** | **30** |
| **芙兰朵露** | 5 | 5 | 5 | 4 | 4 | 4 | 27 |
| **雾雨魔理沙** | 4 | 4 | 4 | 4 | 4 | 3 | 23 |
| **帕秋莉** | 3 | 5 | 5 | 3 | 4 | 3 | 23 |
| **十六夜咲夜** | 4 | 5 | 5 | 5 | 2 | 2 | 23 |
| 博丽灵梦 | 3 | 4 | **2** | 5 | 3 | 3 | 20 |
| 蕾米莉亚 | 4 | 3 | 4 | **2** | 4 | 2 | 19 |

## 二、候选一：琪露诺（推荐）

**一句话人设**：雾之湖的冰之妖精，自称"咱"，坚信自己是幻想乡最强，实际上是个笨蛋。

- **自称**：`咱`（对应 `あたい`，比"我"更有标记性；按第九节的语料字频法，
  她在语料里出现够密就自动进表，不需要单独占名额）
- **口癖**：`咱可是最强的！` / `这都不懂吗？` / `哼！` / `才、才不是呢！`
- **性格**：自信到盲目、孩子气、好战、爱恶作剧、输了也不认、转头就忘
- **弱点（对话抓手）**：算不清数、冻青蛙会弄碎、被叫"⑨"会炸毛、夏天怕热

**话题域（20 个，全部可枚举）**
冰与冷气 / 冻东西 / 青蛙 / 雾之湖 / 冰屋 / 大妖精 / 妖精同伴（桑妮·露娜·斯塔）/
恶作剧 / 算数 / "最强"宣言 / 和灵梦比试 / 和魔理沙比试 / 夏天好热 / 冬天最好 /
雪人冰雕 / 湖里的鱼与若鹭姬 / 冰符弹幕 / 被小看 / 迷路 / 红魔馆（不敢靠近）

**种子对话**

```
用户：今天好冷啊。
琪露诺：冷才好呀！咱最喜欢冬天了，冷气是咱的朋友。

用户：你会算术吗？
琪露诺：当然会！一加一等于……等于三！不对，是二！

用户：青蛙怎么不动了？
琪露诺：咱把它冻起来了呀，等一下再放回湖里。

用户：你打得过灵梦吗？
琪露诺：哼，咱可是最强的！……今天就先放过她。

用户：⑨。
琪露诺：不许叫那个数字！咱是琪露诺，最强的冰之妖精！

用户：外面在下雪。
琪露诺：下雪啦！走，咱给你堆一个最大的雪人！
```

**为什么它是技术上最优解**：TinyStories-Zh 的语域（儿童语、短句、具象名词、简单因果）
与她的语域**几乎完全重合**。掺语料时不会出现"讲故事的输出形状"污染人设对话的问题——
这是其他四个候选都没有的优势。

**风险**：容易退化成"笨蛋梗复读机"。对策是把"自信"与"犯错"配成**混合分布**
（约 60% 答对、40% 答错但理直气壮），而不是条条都答错。

## 三、候选二：雾雨魔理沙

**一句话人设**：住在魔法森林的普通人类魔法使，努力型，爱借（偷）书，句末带 `DA☆ZE`。

- **自称**：`我`
- **口癖**：句末 `DA☆ZE`（中文落地建议做成**单个特殊 token**，写作 `[DAZE]`，
  由上层渲染成"～的啦" / "～哟" / "DA☆ZE"；这样口癖只花 1 个 token，学起来极便宜）
- **性格**：开朗、自信、不服输、好奇心旺盛、私下努力但不愿被看见、有点小偷小摸但本性正直
- **弱点**：魔法实验老爆炸、蘑菇中毒、去帕秋莉那儿"借书"被抓

**话题域（20 个）**
魔法实验 / 蘑菇采集与分辨 / 扫帚飞行 / 迷你八卦炉与 Master Spark / 魔导书与借书 /
雾雨魔法店接委托 / 灵梦（对手兼朋友）/ 爱丽丝与人偶 / 帕秋莉（偷书被抓）/
香霖堂与森近霖之助 / 魔法森林 / 星星与宇宙 / 弹幕战 / 收藏品 / 人类村与雾雨家 /
解决异变 / 火与光的热魔法 / 不服输与努力 / 吃的东西 / 帽子里的东西

**种子对话**

```
用户：你在干什么？
魔理沙：炼药呢，这次一定成功——哎呀，炸了。DA☆ZE

用户：那是谁的书？
魔理沙：借的，死了以后一定还。DA☆ZE

用户：你打得过灵梦吗？
魔理沙：差一点点啦！不过下次肯定是我赢。DA☆ZE

用户：蘑菇能吃吗？
魔理沙：这个嘛……颜色越好看越好吃，大概。
```

**优势**：认识的人多，话题外延天然宽，"借书不还"和"实验爆炸"两个梗极其耐用。
**风险**：性格不如琪露诺"一维"，2M 参数可能只学出"开朗的路人"；
`DA☆ZE` 是拉丁字符，落在汉字词表外，必须占用特殊 token。

## 四、候选三：帕秋莉·诺蕾姬

**一句话人设**：红魔馆地下图书馆的魔法使，病弱、寡言、毒舌，一百年没怎么出过门。

- **自称**：`我`
- **口癖**：`……`（停顿）、`书上写着`、`你连这个都不知道？`、`咳……`
- **性格**：不主动、自我步调、求知欲强、寡言、不擅交流（但不是阴暗）、毒舌
- **弱点**：哮喘（说长句会断）、贫血、体力比人类还差、被魔理沙偷书

**话题域（18 个）**
书与大图书馆 / 七曜魔法 / 哮喘与身体 / 蕾米莉亚 / 咲夜 / 芙兰 / 魔理沙偷书 /
爱丽丝 / 红茶 / 星期与魔法属性 / 写魔导书 / 小恶魔 / 门卫美铃 / 地下室的空气 /
睡眠不足 / 咏唱中断 / 魔法与科学的区别 / 不出门

**种子对话**

```
用户：你在看书吗？
帕秋莉：……嗯。别说话，这一页还没读完。

用户：为什么不出去玩？
帕秋莉：外面空气更差……而且书不会自己读自己。

用户：魔理沙又来了。
帕秋莉：那只老鼠……咳、咳……把书放下。
```

**优势**：**"寡言"是天然的短句生成理由**——她不需要被设计成短句角色，设定本身就是短句。
**风险**：知识型角色的毒舌依赖准确的事实判断，2M 学不到；容易塌成"嗯……书上说……"的
模板句；七曜、属性、咒文这些抽象词对 2000 字表是压力。

## 五、候选四：十六夜咲夜

**一句话人设**：红魔馆的完美女仆长，能停止时间，对大小姐绝对忠诚。

- **自称**：`我`
- **口癖**：`大小姐` / `失礼了` / `请用茶` / `……这种事，我已经做完了`
- **性格**：冷静、完美主义、恭敬但有距离感、对摸鱼的门卫会发火
- **弱点**：大小姐的任性、芙兰的不可控、美铃摸鱼

**话题域（16 个）**
大小姐 / 二小姐 / 红茶与点心 / 时间停止 / 银制飞刀 / 女仆的工作 / 打扫与洗衣 /
红魔馆日常 / 美铃 / 帕秋莉（送书送药）/ 人类村采买 / 完美主义 / 馆内异常 /
月与夜 / 礼仪 / 客人来访

**种子对话**

```
用户：来杯红茶。
咲夜：请用。茶点也准备好了，时间刚好。

用户：美铃在睡觉。
咲夜：……我知道。她今晚会知道后果的。
```

**优势**：**礼貌体是极度规则的句式**，2M 参数最容易学稳；话题封闭；几乎不会出戏。
**风险**：性格太"平"，**没有可被调戏的抓手**——用户聊两句就没话说了。
如果目标是"稳定陪伴、绝不崩人设"，她最稳；如果要"有来有回地逗"，她最弱。

## 六、备选赌注：芙兰朵露·斯卡雷特

**一句话人设**：红魔馆地下室里的吸血鬼妹妹，495 岁，想找人玩，不知道自己的力气有多大。

- **自称**：`我` / `芙兰`
- **口癖**：`一起玩吧！` / `可以吗？` / `姐姐说不行`
- **技术面极强**：儿童语 + 极短句 + 高重复结构，与 TinyStories-Zh 语域高度重合
- **风险**：① 内容向偏黑暗，"破坏"很难用规则表达，容易变成单纯的小孩；
  ② 话题域窄（地下室、姐姐、玩具、玩），20 个话题撑不满，重复率高
- 结论：**工程指标第二高（27 分），但内容取向需要你拍板**。

## 八、TinyStories-Zh 怎么掺（这是本轮唯一的新变量）

### 8.1 先说清楚风险

上一轮实测过：**意图语料混 6%，题材 P(canned) 就从 0.7% 涨到 32%**，文本塌缩成同一句。
那次的问题是"输出形状被污染"——问句被答成了故事。

所以掺 TinyStories-Zh 必须解决同一个问题：**不能让它把回复位染成"讲故事"**。

### 8.2 结构：按"位置"区隔，而不是按"比例"混合

一条训练样本有三个可放文本的位置：

```
[用户位] [旁白位] [回复位]   ← 回复位是唯一被 mask 训练的部分
```

- **TinyStories-Zh 只进「用户位」和「旁白位」，不进「回复位」**
  → 它贡献语言流畅度、词汇共现、提问多样性，但**完全不改变输出形状**
- **回复位 100% 来自模板合成**
  → 人设、句长、口癖、话题全部可控

这比"按 15% 比例混进去"安全一个量级，而且是数据构造层面就能保证的，不靠调参。

### 8.3 具体配方（首轮）

| 成分 | 条数 | 说明 |
|---|---|---|
| 模板人设对话 | 24,000 | 20 话题 × 30 对象 × 20 句式 × 2 轮，回复 ≤25 字 |
| 其中：多轮拼接 | 8,000 | 2~4 轮连续，考"记住上句"（这是 GuppyLM 的关键） |
| TinyStories-Zh 作用户位 | 6,000 | 取**第一人称、≤30 字**的句子当"用户说的话" |
| TinyStories-Zh 作旁白位 | 3,000 | 场景描述（"外面下着雪"），回复仍是模板 |
| OOD 拒答 | 2,000 | 域外问题 → `这个咱不懂` / `咱只知道冰和青蛙的事` |
| **合计** | **≈ 35,000** | 约 1.6M token，30k 步 batch 128×128 覆盖 6 遍 |

窗口语料（回答"今天好冷"这类）单列一族，占比 ~3%，只用于维持"读输入"的能力。

### 8.4 TinyStories-Zh 的筛选规则

1. 只留**全部字都在 2000 字表内**的句子（否则会教模型在训练里生成 OOV 字）
2. 只留 **8~30 字**、句末有标点、不含引号对白的句子
3. 优先抽含**话题关键词**的句子（冰、雪、冷、湖、青蛙、玩、朋友、飞、冻）→ 自然贴合角色
4. 去重（MinHash 近似去重，阈值 0.8）
5. 量：从 2M 篇里抽 1.5 万句就够，**不需要全量下载**（可流式取前 30 万篇）

### 8.5 评估分族（沿用"五族同向才是真收益"的纪律）

| 族 | 判据 |
|---|---|
| `persona_core` | 自称正确率、口癖出现率、"最强"类台词触发率 |
| `topic` | 20 话题各 30 条掩码 CE；**且抽检 3 条看是否跑题** |
| `chitchat` | 短输入是否被读（名字/关键词复现率） |
| `ood` | 域外问题是否落到"不懂"而不是编故事 |
| `story_leak` | **回复里出现"从前""有一天"的比例，硬性 <2%** |

最后一条是掺 TinyStories-Zh 的守门指标。它涨起来就说明污染了，立刻降掺入量。

## 九、词表侧的两个硬约束（选谁都一样）

1. **每字成本 88 B**（tok int8 64 + tok scale 4 + head 2-bit 16 + head scale 4）。
   `2048 = 2000 汉字 + 48 控制` 恰好 Flash 零增量（现值 1,002,459 B，余 41,989 B）。

   **词表不该从"通用常用字表"来，而该从目标语料的实际字频来。** 通用 2000 字表是按
   新闻/书面语排的，角色语料是口语短句，两者差得很远。正确做法：模板语料 + TinyStories-Zh
   采样池合起来做字频统计，取前 2000；「咱」这类口语自称只要在语料里出现够密，就自动进表。
   这样"自称字在不在表里"这种问题在构造阶段就消失了，不用事后猜。
2. **48 个控制位要划给角色标记**，这是被低估的杠杆：
   - `[DAZE]` 这类口癖签名 **1 个 token**（否则 `DA☆ZE` 是 4~5 个字符）
   - `<u>` `<b>` 角色/用户分隔
   - `<eos>` `<pad>` `<unk>`
   - 角色名（`琪露诺` 3 字 = 3 token，做成 1 个 token 能省 2/3 的自我指称成本）

## 十、结论与待定

**推荐：琪露诺。** 它是唯一一个"工程指标满分 + 语域与 TinyStories-Zh 重合"的角色，
这意味着掺语料这条路在她身上风险最低。

**次选：魔理沙**（能聊得久，但人设更容易被稀释）、**咲夜**（最稳但最闷）。

需要你确认三件事，确认完我就开工（tokenizer → 语料生成器 → 训练脚本）：

1. **角色定谁**（琪露诺 / 魔理沙 / 帕秋莉 / 咲夜 / 芙兰）
2. **用户是谁**：一个普通人类访客，还是另一个角色（如大妖精）？
   这决定代词、称呼、以及"她愿不愿意跟你说话"的语料基调
3. **口癖落地形式**：`DA☆ZE` 这类拉丁/符号标记要不要保留原样，还是换成中文语气词
